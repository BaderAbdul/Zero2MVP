# From Zero to MVP: Program Blueprint

## 1. Program Positioning
**Name:** From Zero to MVP  
**Positioning:** AI Product Builder Experience  
**Core Promise:** "Turn a real problem into a live digital product in 3 days using AI."

## 2. Target Audience
This program is designed for aspiring founders, product thinkers, and builders who want to move past the "idea phase." It is for individuals ready to leverage AI to overcome technical barriers and ship functioning software. 

## 3. Learning Philosophy
The program is a product-building experience, NOT primarily an AI tools course. Participants learn by doing. The AI tools are the engine, not the destination. We focus on pragmatic, accelerated building rather than traditional coding tutorials.

## 4. Builder Journey
There is only one participant-facing progression system. Participants evolve through five distinct levels:
1. **🎯 Problem Hunter** (Mission: DISCOVER)
2. **📐 Product Architect** (Mission: DESIGN / FIRST SHIP)
3. **⚙️ AI Builder** (Mission: BUILD)
4. **🌐 MVP Creator** (Mission: CONNECT)
5. **🏆 Founder** (Mission: SHIP + PITCH)

## 5. Product Progression (Internal Technical States)
Behind the scenes, the internal technical architecture mirrors the participant journey:
- **IDEA / VALIDATED PROBLEM** (Maps to Problem Hunter)
- **DEPLOYED SHELL** (Maps to Product Architect)
- **FUNCTIONAL PROTOTYPE** (Maps to AI Builder)
- **CONNECTED MVP** (Maps to MVP Creator)
- **LIVE PRODUCT** (Maps to Founder)

## 6. Program Principles (Builder Rules)
- **Build small.** Scope must be aggressively reduced.
- **Ship ugly.** Visual polish is secondary to functional core loops.
- **Test early.** Get it working before making it pretty.
- **Ask AI, don't worship AI.** Use AI to accelerate, but maintain builder agency.
- **Use the 15-minute rule.** Never stay stuck on a single bug for more than 15 minutes.
- **Demo what works.** Only show functioning software, no vaporware.
- **Use Starter Kits without shame.** Accelerators are valid tools.
- **Focus on the core user flow.** One primary journey is all that matters.

## 7. Technology Stack
The core tech stack is taught as a continuous action loop:
- **Antigravity = BUILD** (Frontend and UI logic)
- **Firebase = CONNECT** (Database, Auth, and Backend logic)
- **Vercel = SHIP** (Hosting and Deployment)

## 8. Mission Architecture
- **Discover (Day 1):** Find a real problem worth solving.
- **Design / First Ship (Day 1):** Turn the validated problem into a buildable product scope and deploy a working shell.
- **Build (Day 2):** Build the core product experience (Functional Prototype).
- **Connect (Day 2):** Turn the prototype into a connected product with data persistence.
- **Ship + Pitch (Day 3):** Final verification, production deployment, and presentation.

## 9. Gamification
The experience uses one visible progression system. Teams earn badges upon completing mentor checkpoints:
Problem Hunter → Product Architect → AI Builder → MVP Creator → Founder.
Progress is tracked visibly (e.g., via a Leaderboard and Builder Passport) to motivate teams, not penalize them.

## 10. Demo Day
Demo Day measures what participants were taught. Judging prioritizes solving the problem and demonstrating a working core user flow over visual polish ("Ship Ugly"). Judging breakdown:
- Problem: 20%
- Core User Flow: 15%
- MVP Execution: 25%
- AI Integration: 20%
- Pitch: 20%

## 11. Success Metrics
Program success is measured by progressing teams from Idea to Pitched Product. Success is mapped to the internal technical progression (Idea → Validated Problem → Deployed Shell → Functional Prototype → Connected MVP → Live Product → Pitched Product).
